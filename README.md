# TradeMaster Pro — منصة تحليل وتداول تجريبية

منصة ويب عربية/إنجليزية لتحليل الأسواق، الرسوم البيانية، الاستراتيجيات، الاختبار التاريخي، إدارة المخاطر، التعليم، ومحاسبة التداول الافتراضي. تعمل من المتصفح على الكمبيوتر والهاتف.

> **تحذير مهم:** هذا المشروع أداة تعليمية وتحليلية ومحاكاة فقط. لا يرسل أوامر إلى وسيط تداول، ولا يحتفظ بمفاتيح API للوسطاء، ولا يُعد نظاماً صالحاً لإدارة أموال حقيقية. بيانات السوق تأتي من مزودين عامين وقد تتأخر أو تنقطع.

## التشغيل محلياً

يتطلب Python 3.10 أو أحدث. لا يتطلب حزم Python إضافية؛ `requests` اختياري لتحسين بعض اتصالات HTTP، ويوجد بديل من مكتبة Python القياسية.

```bash
python server.py
# افتح http://localhost:8000
```

يقرأ الخادم `HOST` و`PORT` من متغيرات البيئة، ويستمع افتراضياً على `0.0.0.0:8000`.

## الاختبارات

```bash
python test/run_checks.py
```

تجري الاختبارات المتاحة فحص صياغة Python وJavaScript، واختبارات حسابات محاكاة التداول، وتشغيل خادم محلي، وفحص نقطة الصحة والملفات الثابتة وحماية مسارات الملفات. تتطلب اختبارات JavaScript وجود Node.js.

## النشر على Render

يتضمن المشروع ملف `render.yaml` جاهزاً لـ Render Blueprint. بعد رفع **محتويات هذا المجلد إلى جذر مستودع GitHub**:

1. افتح Render واختر إنشاء Blueprint جديد.
2. اربط مستودع GitHub الذي يحتوي على `render.yaml` في الجذر.
3. راجع إعداد الخدمة `trademaster-pro` ثم ابدأ النشر.
4. بعد النشر افتح رابط `onrender.com` الذي توفره Render، ثم تحقق من `/api/health`.

يستخدم الإعداد `python server.py`، ويستمع الخادم على `0.0.0.0` والمنفذ الموجود في `PORT`، ويستخدم `/api/health` لفحص الجاهزية. راجع دليل Render الرسمي: [Web Services](https://render.com/docs/web-services) و[Blueprint YAML](https://render.com/docs/blueprint-spec).

## حدود يجب معرفتها قبل النشر

- **لا توجد حسابات مستخدمين أو قاعدة بيانات.** التفضيلات، الخطة، السجل، والتداول الافتراضي تُحفظ في `localStorage` داخل المتصفح؛ لذلك لا تتزامن تلقائياً بين الهاتف والكمبيوتر أو بين المتصفحات.
- **مراقبة وقف الخسارة وجني الربح في التداول الافتراضي تعمل كل 30 ثانية أثناء بقاء التطبيق/علامة التبويب مفتوحة واتصال الإنترنت متاحاً.** لن تراقب الصفقات بعد إغلاق المتصفح أو الجهاز، ولا يوجد تنفيذ مضمون عند سعر معين.
- أوامر الوقف في المحاكاة تُغلق على سعر السوق المرصود عند تحقق الشرط، لذلك يمكن أن يكون التنفيذ أسوأ من سعر الوقف عند حدوث فجوة. الأهداف تُحاكى كأوامر حدية عند سعر الهدف.
- أسعار الأسواق والأخبار والمقاطع تعتمد على خدمات عامة خارجية. يجب توقع تحديد المعدل، التأخير، التوقف، أو تغيّر واجهات المزودين.
- الخادم الحالي خفيف ومناسب لنشر تجريبي محدود. قبل إطلاق عام واسع، أضف قاعدة بيانات ومصادقة وحدود طلبات ومراقبة وأتمتة نسخ احتياطي. لا تخزن بيانات خاصة أو أسراراً في المستودع.
- إعداد Render يجعل المشروع متاحاً عبر HTTPS خلف خدمة الاستضافة؛ لا تضع خادم Python مباشرة على الإنترنت دون طبقة استضافة/عكس وكيل توفر TLS.
- لم يُحدّد ترخيص لإعادة استخدام كود المشروع نفسه. رفعه إلى مستودع عام لا يعني تلقائياً منح الآخرين حق إعادة استخدامه؛ راجع أيضاً شروط منصة Arena ومصادر الأصول قبل النشر العام.
- الخطوط المضمّنة IBM Plex Sans Arabic وJetBrains Mono تتضمن إشعارات وترخيص SIL OFL 1.1 في `public/fonts/`.

## مصادر البيانات

| السوق/الخدمة | المصدر الأساسي والبدائل |
|---|---|
| العملات الرقمية | OKX → Coinbase → Kraken → CoinGecko |

## حالة التحقق الحالية

اجتاز المشروع الاختبارات المحلية المضمنة في `test/run_checks.py`، بما فيها اختبار محاكاة انقطاع مزود البيانات والتأكد من إرجاع HTTP 503 بدلاً من إخفاء الانقطاع كاستجابة ناجحة. يوجد تقرير بنتائج فحص المتصفح والقيود المعروفة في `test/REPORT.md`.

**تنبيه بشأن اختبار الأسعار الحية:** بيئة الفحص التي بُنيت فيها هذه الحزمة لا تسمح باتصالات DNS/الإنترنت إلى مزودي السوق؛ لذلك لم يمكن إثبات وصول الأسعار الحية من هذه البيئة. بعد النشر، اختبر `/api/quote` و`/api/klines` من رابط الخدمة. ظهور HTTP 503 يعني أن مزودي البيانات غير متاحين من بيئة الاستضافة في تلك اللحظة، ولا يعني أن واجهة التطبيق معطلة.
